## 2. 必须修改的实现

### A. 论文主配置与历史对照分开

当前 `runner.RunConfig` 默认固定角色、listwise，仍需对齐论文；`config.py` 默认 DeepSeek 则符合用户的固定约束，不需要更换基座。

建议提供明确的论文优先配置与官方代码兼容配置，避免继续依靠多个零散开关暗示“论文保真”。下列配置名是建议接口，尚未实现：

- `paper_aligned`：固定 `deepseek-flash`、关闭思考，4 agents，最多3轮，temperature 0.2，每轮随机角色，首轮混合偏置，第三轮实际按 importance 选两名 agent。这里的aligned指流程与评测对齐，不表示基座与原论文相同。
- `official_compat`：保留固定四个 knowledge graphs expert、listwise、原激活及解析行为，用于解释公开代码，不能冒充论文配置。
- 全 normal 等偏离论文主流程的配置保留为显式改进实验。所有主对照、消融与历史兼容对照使用相同 DeepSeek 基座和思考设置，单独分析实现差异，不再追求原模型调用或将趋势一致作为成功条件。

证据：论文 p6 §5.3、p7 §6；`src/mrbalance_replay/config.py:17-22`、`runner.py:54-76`、`agents/graph.py:87-95`。

### B. 修复 importance，而非只打开现有 importance 开关

论文 p5 §4.4、式(12)和 p6 式(13)明确要求：沿边权回传每层节点贡献，然后将同一 agent 在各轮的贡献求和，再 top-k。

当前 `_compute_importances` 已计算早期层贡献，但 `_select_importance_agent_ids` 只按上一轮节点分数排序，忽略了此前各层贡献。它实际主要按“上一轮多数答案”选人，不能仅用“论文初始化未公开”解释该偏差。

修改要求：在第三轮开始前，对已发生轮次的节点贡献按稳定 agent ID 累加，再选择 top2；始终激活这两个实际 ID。保留官方边权解析/归一化作为评分细节回退。末层初始化、临时参考答案、top-k 同分规则未被论文完整定义，应逐项记录采用的假设。

离线反例：两层贡献分别为 `[0,0,0,1]` 与 `[0.5,0.5,0,0]`，当前选择 `[0,1]`；式(13)总分是 `[0.5,0.5,0,1]`，应优先选 agent3。该差异不依赖在线模型。

证据：`agents/graph.py:370-447`，尤其 `434-438`；现有 `tests/test_debate.py:368` 将“选上一轮多数派”写成测试期望，需要替换为式(12)/(13)手算验证。

### C. 最终平票随机选择

论文 p4 §4.3.2明确：达到最大轮数仍无共识、最高频答案并列时，随机选择其中一个答案。当前 `most_frequent` 平票取第一个，最终 fallback 直接复用它。

只修改最终无共识决策：从并列最高频的不同有效答案集合中，以样本级 RNG 选择。不能因该要求而随意改变中间共识计数、importance 临时参考答案或 top-k 同分规则。官方兼容配置继续保留历史 first-on-tie 行为。

证据：`parsing.py:48-61`、`agents/graph.py:359-361`。

### D. 补齐上一轮回复的摘要/聚合层

论文 p5 §4.3.3明确说明整合前执行 summarization，以减少冗余。当前和官方代码都直接将前轮原始回复逐个拼入提示词，缺少此步骤。

新增可独立检查的摘要/聚合接口，保留原始回复、摘要、来源 agent ID、评分对应关系及实际请求。不要改变“下一轮接收上一轮集体信息”的邻层语义。

论文没有公布摘要算法、提示词、模型或是否新增调用；官方也无法填补。因此具体摘要策略仍是待冻结的实现假设，不能自行增加一个摘要 LLM 后声称严格恢复。实现前应将选择及成本影响写清；暂不实现时必须标注“摘要细节未恢复”。

证据：`agents/neuron.py:113-146`、`prompts/templates.py:157-171`。

### E. 补齐论文优先的单模型基线

论文 p3 §4.1规定输出选项和理由，但未给完整单模型请求或解析代码；p2 Fig.1只提供示意，不能将它当成完整 API 请求。

按用户原则，对未明确部分回退配套 `ECI.py`：复用其零样本 system/user 文本及完整答案解析路径。原文 §5.3明确 temperature 0.2、没有声明单模型例外，因此主配置温度保留0.2，覆盖 `ECI.py` 的0；温度0仅归入代码兼容配置。`max_tokens=1024` 为代码回退细节。

当前单模型用辩论问题模板和最后明确选项解析，不能仅改名称当成对齐。更改提示词需要新调用；旧回复只能用于后处理敏感性分析。

当前 `naive` 也不是官方单模型完整解析：缺少 `response.split("Answer:", maxsplit=1)[-1]`。应新增精确官方解析路径，保留当前明确选项解析为诊断列，不再把两者混称。

单模型 causal analysis expert 角色的语义已一致；官方文本额外有前后空白。按字面复用时保留原字符串即可，不应将其当成模型能力差异。

证据：官方 `CausalDebate/ECI.py:134-170,190-203`；本地 `data.py:15-20`、`runner.py:262-290`、`parsing.py:64-79`。

### F. 明确无法解析与失败的评测口径

论文没有给解析失败政策。公开辩论入口将最终 `None` 回退为 C/0；本地保留 `None` 并从指标分母排除，二者不一致。

论文优先配置应对成功返回但无法生成有效最终选项的记录采用明确、可追溯的官方回退政策，并保留原始状态/有效性统计。API 失败是另一类情况，不得伪装成模型预测 none，也不得静默删除后称全量评测完成。主结果应在请求全部完成、覆盖数核对后发布，并报告回退数。

现有单模型 CTB 1198条中1条无有效选项，主指标按1197条计算；该行 gold=0，若按兼容回退计0，F1不变，但 N、负类召回和 Accuracy 改变。当前 ESC 没有这类缺失。

证据：官方 `Muty_agent_debate.py:117-125`；本地 `runner.py:191-204`、`evaluation/metrics.py:145-177`。

### G. 如要覆盖论文 Table 3，补齐实际执行路径

现有实验只有单模型以及角色/提示词消融，没有完整覆盖论文 p6-7 §5.6 的两个模块消融：

- w/o Multi-Rounds：只运行第一轮，用该轮结果作最终决策。
- w/o Consensus Check：关闭共识早停，且同时关闭 team member optimization，完成全部轮次后决策。

当前图固定展开前两轮，`forward` 断言 `rounds > 2`，所以 CLI 接受 `--rounds 1` 不代表真正支持单轮。需要将轮次、共识与 TMO 的执行控制独立。现有 top2 测量脚本中的强制轮次不等价于第二种消融。

这不要求机械补做论文全部其他方法的 SOTA 基准；但不能再把角色/prompt消融描述为已经完整复现 Table 3。

## 4. 已经对齐或应保持的部分

- 温度0.2、4 agents、最多3轮、第三轮2人、首轮混合偏置及后轮不再附加偏置。
- 严格超过2/3的共识阈值。Algorithm 1 的 `>=` 与正文有内部差异，采用 §5.3更具体的“more than 2/3”，不擅改为非严格比较。
- 轮内早停：p9 §6.7明确三个agent在第二轮选A便跳过后续agent，不能因为算法框图看似整轮检查而强制所有人先答完。
- 下一轮收到上一轮集体信息；无需擅自增加长期个人记忆、所有轮全文或外部检索。
- A/B合并因果正类，C为负类；P/R/F1按论文公式，不将其改成全类别micro-F1（会等于Accuracy）。
- 配套评分模板、1-5分解析和边权归一化，在论文未定义具体评分细节处可复用；其来源应标成代码回退。
- 复用配套JSONL测试数据合理。离线核对九个主run与对应文件的输入内容集合一致；ESC1600条，CTB1198条。CTB仅275个不同item_id，内容指纹1198个唯一，因此不能恢复按item_id去重。
- 两个数据集均为当前句内测试；缺少type字段时本地按intra处理是schema适配，不代表已做跨句实验。ESC含500个正类/1100个负类，CTB含298个正类/900个负类。
- 并发、依赖注入、断点恢复、类型检查、原始回复归档等成功请求语义不变的工程措施保留。

## 6. 已有实验与文档如何处理

不删除或覆盖九组主归档，不更改其原始meta或数值。

| 现有结果 | 继续可用的用途 | 不再支持的表述 |
| --- | --- | --- |
| official-esc/ctb | DeepSeek下按当时官方默认配置的历史对照 | 原论文同条件主结果 |
| paper-esc/ctb | 旧随机角色加上一轮多数派式importance近似的历史实验 | 已完整恢复论文importance；随机角色/真实importance无收益 |

| top2旧配对测量 | 当时listwise及共享全文上下文下的选员缺陷条件测量 | 对修复累计importance、摘要等新流程仍然保证无影响 |

必须修正的叙述包括：

1. 将“只靠两项开关即论文保真”的说明改成逐项来源/差异表。
2. 撤回“这些结果说明随机角色和importance不是提升来源”的归因：当前importance未实现式(13)。
3. 单seed结果不称“唯一稳定改进”；多seed可增强当前DeepSeek条件下的证据，但不能消除已知基座差异，也不能代替机制对齐。基座不同本身不使现有实验无效。
4. 本地all-normal优于mixed，不是论文Table10的同趋势复现；论文mixed65.3高于all-normal64.3。Table9单角色设置不能替代Table10组合设置作对照。
5. “降低早停阈值可增加多轮”方向相反。研究多轮可提高阈值或关闭早停，但属于额外实验。
6. 只有第三轮的选员机制受第三轮触达率约束，角色与首轮提示偏置也作用于第一轮；不能把全部机制都说成只影响1-2.5%的样本。

## 7. 验证与补跑顺序

1. 先冻结论文优先契约、实现假设和配置来源，再修改算法与对应测试。
2. 离线验证式(12)/(13)手算传播与累加，确保改变早期边权可改变top2；测试实际agent ID激活。
3. 验证最终平票只从并列最高频不同选项随机采样，同seed可复现；保留三票可轮内早停的检查。
4. 核对单模型system/user字面文本、温度0.2、精确官方解析（含Answer截取）及额外诊断列；对错误/无选项回退核对分母与覆盖率。
5. 验证摘要来源映射、评分对应与成本；分别验证真正单轮、关闭共识且关闭TMO的消融。
6. 验证换配置拒绝混合续跑、同配置可恢复、每个record恰有一个最终结果，清单包含实际生效参数。
7. 固定现有DeepSeek基座与关闭思考设置，在运行预算明确后先做小样本接口/格式检查，再新run-id运行论文优先单模型与MRBalance的ESC/CTB主对照，随后补Table3消融。对只改变解析/计分的旧结果可离线补算；提示词和流程变化的结果不能靠旧归档恢复，必须新运行。无需因模型不变而重跑任何语义未改变的配置。

本轮已运行主项目149项离线测试，全部通过。通过只证明当前测试期望成立，不证明论文对齐：现有部分测试固定了官方默认与旧importance选择。未新增模型调用，未修改源代码、配置、旧结果或已有文档；本文件为唯一新增审计报告。
