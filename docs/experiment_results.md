# 全量复现与改进实验结果

> 运行日期：2026-10-24。模型 `deepseek-flash`，`reasoning_effort=none`，temperature 0.2，
> 4 agents × 3 rounds，seed 0，共识阈值 2/3。ESC 全量 1600 条、CTB 全量 1198 条。
> 每个 run 的配置、commit、数据/输出 sha256 与指标见 `experiments/<run-id>/meta.json`；
> 原始回复见 `experiments/<run-id>/response.jsonl.gz`。本页数字均由 gzip 原始回复独立重算。
> 2026-10-25 追加 §3.5（第 3 轮触达率）、§3.6（top-2 缺陷实测）与 §5 的复现性说明；
> 这些数字来自配对分叉复放，不属于 9 组主实验，原始结果在 `outputs/top2-pilot/`（本地，未入库）。

|---|---|---|---|---|---|

## 3. 主要发现

### 3.1 多智能体辩论并非稳定优于单 agent

- ESC：单 agent F1 **67.7** > 官方辩论 **62.9**（+4.8）。
- CTB：单 agent F1 **63.4** < 官方辩论 **67.1**（+3.7 反过来）。

即"辩论是否有效"在本模型上依赖数据集。辩论的主要作用是压低正类召回、抬高精确率
（ESC P 61.4→66.5、R 75.6→59.6），属于保守化偏移；在负类占比 75% 的 CTB 上，这种保守化
恰好有利，在 ESC 上则损失了过多正例。

这也解释了为什么与论文数字不能直接对齐：论文的单 LLM（GPT-4o-mini）是"高召回、低精确"
（ESC R 95.4 / P 41.7），而 `deepseek-flash` 单 agent 本身已接近平衡（75.6 / 61.4），
辩论能带来的平衡空间更小。

### 3.2 论文保真度开关没有带来提升

- ESC：`paper` 与 `official` 的 F1 都是 62.9（62.90 vs 62.87）。
- CTB：`paper` 65.7 < `official` 67.1（-1.4）。

"每轮随机角色分配 + importance 选 top-2"是论文相对官方代码的两处差异。本实现中
importance 是基于上一轮答案与边权回传的近似（论文未公开评分细节），区分度有限；结果说明
这两项差异不是性能提升的来源。另外随机角色会引入额外方差，单 seed 下也无法排除噪声。

### 3.3 角色平衡单独使用反而略降

`imp-role-balanced`（expert + causal + NLP + none）F1 62.5，比 4 个相同 expert 的 62.9
低 0.4；精确率 66.5 → 65.4、正类召回 59.6 → 59.8，两边都没有实质改善。差距在单 seed
噪声范围内，不能支持"角色分工有独立增益"。

与 prompt 全 normal 组合后（`imp-role-prompt`）F1 65.4，与只改 prompt 的 65.3 几乎相同，
进一步说明本模型上角色配置不是主要因素。

### 3.4 prompt 偏置是唯一稳定的正向改进

把默认的 `positive/normal/normal/negative` 换成四个 `normal`：

- ESC F1 62.9 → **65.3**（+2.4）；
- 正类召回 59.6 → 66.2（+6.6），精确率 66.5 → 64.4（-2.1），负类召回 86.4 → 83.4（-3.0）。

效果与论文 Table 9 的"Normal 偏置降低正类偏置、提升 F1"方向一致，但在 deepseek-flash 上
幅度更小，且以少量负类召回为代价。

### 3.5 辩论实际很少跑到第 3 轮

按每条响应行的 `n_calls` 反推轮次：3/4 表示第 0 轮结束，7/8 表示第 1 轮结束，
10/11 表示进入第 2 轮（第 3 轮；10 表示选中的 2 人里有 1 人未激活）。

| run | n | 进入第 3 轮 | 占比 | `n_calls` 分布 |
|---|---:|---:|---:|---|
| `official-esc` | 1600 | 19 | 1.2% | 3:1224, 4:203, 7:121, 8:33, 11:19 |
| `official-ctb` | 1198 | 30 | 2.5% | 3:844, 4:184, 7:115, 8:25, 11:30 |
| `paper-esc` | 1600 | 30 | 1.9% | 3:1180, 4:223, 7:135, 8:32, 10:30 |
| `paper-ctb` | 1198 | 22 | 1.8% | 3:809, 4:180, 7:146, 8:41, 10:22 |
| `imp-role-balanced` | 1600 | 31 | 1.9% | 3:1182, 4:204, 7:145, 8:38, 11:31 |
| `imp-role-prompt` | 1600 | 16 | 1.0% | 3:1232, 4:214, 7:106, 8:32, 11:16 |
| `imp-prompt-normal` | 1600 | 7 | 0.4% | 3:1382, 4:130, 7:65, 8:16, 11:7 |

- ESC 有 **76.5%**（1224/1600）在第 0 轮、第 3 个 agent 说完时就达成 3 票共识；89.2% 在第 0 轮内结束。
- 因此角色分配、prompt 偏置、top-2 选人等"多轮机制"实际只作用于 0.4–2.5% 的样本。
- 这解释了 §3.2/§3.3 为什么几乎测不出论文设置与角色消融的差异，也说明"多轮辩论"在本实现中
  主要是名义上的：大多数样本只经历了一轮独立作答。

### 3.6 top-2 激活缺陷：实测无影响

官方 listwise 选人用"打乱后的位置"匹配"agent id"，第 3 轮实际上是从 4 个 agent 中随机取 2 个，
ranker 的选择结果被丢弃。修复开关 `--fix-top2-activation` 已接入 runner。

用**配对分叉复放**测量（同一第 3 轮入口状态，仅切换选人规则；用 `--force-rounds` 关闭早停）：

| 样本集 | n | 选中的 agent 对变化 | 答案字母变化 | 二值标签变化 |
|---|---:|---:|---:|---:|
| `official-esc` 归档第 3 轮样本 | 19 | 16（84%） | 0 | 0 |
| `imp-role-balanced` 归档第 3 轮样本 | 31 | 24（77%） | 0 | 0 |

自然设置下的 200 条 pilot 结论一致：两臂指标完全相同（P 64.4 / R 62.3 / F1 63.3），
8 条标签翻转呈 4:4，其中 7 条两臂都没有进入第 3 轮，属于 API 采样噪声。

原因：第 3 轮所有 agent 共享同一组第 1 轮回复，最终答案取 2 人众数；24 次选人变化中 23 次只替换
1 票，不足以改变多数。结论是该缺陷行为上真实存在、结果上近乎无效，**不需要为它重跑主实验**；
详见 `review_findings.md` 的"追加测量"一节。

## 4. 成本

- 辩论：每个样本约 3.3–3.9 次 LLM 调用（含提前共识与 listwise/importance 剪枝），
  ESC 约 5800–5900 次调用 / 2.8M tokens，CTB 约 4600–4700 次 / 2.2–2.3M tokens。
- 单 agent：每样本 1 次调用，ESC 1600 次 / 0.30M tokens，CTB 1198 次 / 0.22M tokens；
  token 约为辩论的 1/9–1/10，调用次数约为 1/3.6–1/3.9。
- `imp-prompt-normal` 的调用数（5326）低于官方（5804），因为全 normal prompt 下更早达成
  共识；token 总量相近。

## 5. 复现与失败记录

- 三个 run（`official-ctb`、`paper-ctb`、`imp-role-prompt`）在运行中遭遇 API 402 余额不足，
  每个数据集分别有 506–623 条 error 行。充值后删除这些无效 error 行并断点续跑，最终
  `failed=0`、记录数等于数据集规模。
- 由于 runner 的续跑是"追加成功行"，错误行不会自动删除；本次在续跑前手工剔除了 402 行。
  后续若再次出现长时间中断，建议在续跑前先按 `error` 字段清理，否则 `response.jsonl` 会
  同时包含失败行与成功行（指标会忽略前者，但记录数会虚高）。
- manifest 的 `stats` 只统计最后一次调用，因此标 `*` 的 run 的 wall time 不可比；
  本页的 calls/tokens 是从全量响应行重新求和的。
- **同配置复跑噪声**：用当前代码重跑 `official-esc` 前 200 条，与归档标签一致 187/200（93.5%），
  13 条不一致（6.5%）。temperature=0.2 下单样本标签有约 5–7% 的抖动，因此 <1 F1 点的差异
  不可判定，必须补 seed 或做配对设计。
- **第 3 轮归属不稳定**：归档的第 3 轮样本自然复跑时，`official-esc` 只有 2/19、0/19，
  `imp-role-balanced` 只有 5/31 再次进入第 3 轮。聚合指标可复现，但逐样本辩论轨迹不可复现；
  报告应区分"聚合可复现"与"轨迹可复现"。

## 6. 局限与下一步

1. **单 seed、单模型、逐样本不稳定**：每个配置只跑了一次，无法给出方差；且 §5 显示单样本标签
   有约 6.5% 的复跑抖动、第 3 轮归属基本不可复现。结论只在 `deepseek-flash`、thinking=none 下成立。
   若要复现论文的相对结论，应换 `gpt-4o-mini` 或至少补多个 seed。
2. **importance 是近似实现**：论文未公开评分与并列处理；当前实现中同一轮多数派 agent
   共享基准 importance，区分度有限。
3. **指标口径**：`R` 为正类召回，`F1` 由 P 与正类召回计算，`Acc` 为总体准确率；与论文一致。
4. **多轮机制覆盖范围小**：第 3 轮只覆盖 1–2.5% 的样本（§3.5），top-2 缺陷亦无数值影响（§3.6）；
   后续若要研究多轮收益，应先降低早停阈值或强制多轮，而不是继续调 top-2 选人。
5. **下一步**：对 ESC 的辩论/单 agent 差异做错误分析（按 inter/intra、正负类、事件对类型）；
   补 seed 方差；再决定是否把"prompt 全 normal"作为默认改进配置。
